## Change

`web/_worker.js/index.js` no longer keeps OCR quota counters in a module-level `Map`. It exports `OcrQuotaDurableObject`, with one named SQLite-backed Durable Object per authenticated user (`ocr:<userId>`). The object initializes a single counter row under `blockConcurrencyWhile()` and performs the read/update through the Durable Object SQL storage API. Durable Object instance serialization and strongly consistent storage provide the shared counter across Worker isolates.

The Worker now treats `env.OCR_QUOTA` as mandatory. A missing binding, invalid stub/result, or limiter exception returns HTTP 503 with `OCR_QUOTA_UNAVAILABLE` and prevents the provider call. A denied limiter result returns HTTP 429 with `OCR_QUOTA_EXCEEDED` and `Retry-After`.

The OCR request body is read through a `ReadableStream` reader. The Worker stops reading and cancels the stream as soon as the 12 MiB limit is exceeded, before joining chunks and decoding JSON. The existing declared `Content-Length` fast path remains in place.

## Deployment configuration

This matches the current Worker + Static Assets Pages layout.
